# Phase 05 Plan 01: Debug And Verification Summary

**Navigation-owned debug snapshots per combat nav area with a passive bot gizmo overlay for nav versions, reachability, resolved spawn facts, and per-tick work counters**

## Accomplishments
- Added `AiNavigationDebugSnapshot` as navigation-owned read-only ECS state on `CombatCellNavArea` entities so debug consumers can inspect nav area shape, build state, nav version, director phase, source counts, resolved source facts, enemy counts, and work-budget counters without mutating director or backend state.
- Added `AiNavigationDebugSnapshotSystem` after the existing navigation pipeline so the snapshot reflects cached reachability, resolved spawn points, current nav work counters, and alive-enemy counts for each nav area.
- Added a dedicated `StaticMlp.Features.AiNavigation.Presentation` assembly with a passive `AiNavigationDebugGizmoPart` that can be wired by a human onto the existing bot view prefab to draw nav-area/debug facts and optional labels in play mode.

## Files Created/Modified
- `Assets/Scripts/StaticMlp/Features/AiNavigation/Runtime/Contracts/AiNavigationDebugSnapshot.cs` - Read-only debug snapshot contract owned by `AiNavigation`.
- `Assets/Scripts/StaticMlp/Features/AiNavigation/Runtime/Logic/Systems/Server/AiNavigationDebugSnapshotSystem.cs` - Aggregates nav/debug facts without mutating director or backend state.
- `Assets/Scripts/StaticMlp/Features/AiNavigation/Runtime/Logic/AiNavigationLogicFeature.cs` - Registers the snapshot system late in the navigation server sequence.
- `Assets/Scripts/StaticMlp/Features/AiNavigation/Runtime/Logic/StaticMlp.Features.AiNavigation.Logic.asmdef` - Adds the combat logic reference needed for alive-enemy counting via `IsDiedTag`.
- `Assets/Scripts/StaticMlp/Features/AiNavigation/Runtime/Presentation/AiNavigationPresentationFeature.cs` - Explicit presentation-module feature entry point.
- `Assets/Scripts/StaticMlp/Features/AiNavigation/Runtime/Presentation/StaticMlp.Features.AiNavigation.Presentation.asmdef` - Presentation assembly for passive debug visualization.
- `Assets/Scripts/StaticMlp/Features/AiNavigation/Runtime/Presentation/ViewParts/AiNavigationDebugGizmoPart.cs` - Passive gizmo/view part that reads snapshot state and existing `AiNavigationRuntime` debug output.
- `.planning/ROADMAP.md` - Marks Phase 05 complete.

## Decisions Made
- Kept the debug contract on `CombatCellNavArea` entities because `AiNavigation` already owns those entities and their nav-area state, so the snapshot can remain strictly navigation-owned.
- Exposed global director phase through `FrontierNavWorkPhaseState` because that is the public, read-only director-facing phase contract already available to other systems.
- Exposed “best reachable” and “resolved reachable” spawn-source facts instead of a fake “director-selected source”, because the current architecture does not publish a director-owned selected-source contract and the debug layer must not invent or mutate one.
- Placed the gizmo part under `Runtime/Presentation/ViewParts/` rather than directly under `Runtime/Presentation/` to follow the project’s approved feature-layout buckets.

## Deviations from Plan

None - plan executed as written within the project’s required feature-layout rules.

## Issues Encountered
- Manual Unity wiring is still required: attach `AiNavigationDebugGizmoPart` to the bot view prefab or another existing bot debug view root in the Unity Editor. No prefab assets were generated by agent code.
- `NavWorkBudgetCounter.PathRequestsThisTick` is now surfaced by the snapshot, but the current `AiNavigation` runtime does not increment that counter anywhere yet, so the debug value will remain `0` until a future path-request producer is introduced.
